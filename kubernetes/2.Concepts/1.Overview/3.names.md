# Object Names and IDs
- Each object has a Name that is unique for that type of resource.
- For example, you can only have one Pod named `myapp-1234` within the same namespace, but can have have one Pod and one Deployment that are each named `myapp-1234`.
  + `Name` đảm bảo unique trong một phạm vi giới hạn, không phải tuyệt đối toàn cluster.
  + Phạm vi giới hạn được xác định bởi 4 yếu tố kết hợp: api group, resource type, namespace, name.
  + Với các resource cluster-scoped, `Name` phải là unique trên toàn bộ cluster.
- Every Kubernetes object also has a UID that is unique across your whole cluster.
  + Tự động sinh ra bở K8s
  + Không bao giờ trùng lặp
  + Cần có UID khi đã có name: UID là cách để Kubernetes phân biệt instance cũ và mới dù cùng tên.
- For non-unique user-provided attributes, Kubernetes provides labels and annotations.

## Names
- A client provided string that refers to an object in a resource URL such as /api/v1/pods/some-name.
  + Name là 1 phần trong URL Kubernetes API.
  + `GET /api/v1/namespaces/default/pods/myapp-1234`
- Kubernetes uniquely identifies object using a combination of four attributes: API group, Resource type, Namespace, Name.
- Names must be unique across all API versions of same resource.
  + Resource Deployment có thể được truy cập qua nhiều API version khác nhau (apps/v1, apps/v1beta1) -> Đọc ghi cùng 1 object trong `etcd`
- Only one object of a given kind can have a given name at a time. However, if you delete the object, you can make a new object with the same name.
  + Object tạo mới có UID khác, dù tên giống hệt nhưng độc lập về mặt hệ thống.
- In cases when objects represent a physical entity, like a Node representing a physical host, when the host is re-created under the same name without deleting and re-creating the Node, Kubernetes treats the new host as the old one, which may lead to inconsistencies.
  + kubelet đăng ký lại node mới với cùng hostname, nhưng không chủ động xóa object Node cũ trong Kubernetes khi máy mới join vào -> Name trùng, Node object cũ trong etcd chưa bị xóa -> UID cũ -> các thông tin cache cũ (capacity, labels, taints) của node cũ overlap thông tin của node mới -> sai lệch scheduling hoặc monitoring.
- The server may generate a name when generateName is provided instead of name in a resource create request. When generateName is used, the provided valie is used as name prefix, which server appends a generated suffix to. Even though the name is generated, it may conflict with existing namess resulting in an HTTP 409 response. The became far less likely to happen in Kubernetes v1.31 and later, since the server will make up to 8 attempts to generate a unique name before returning an HTTP 409 responce.
  + Thường dùng cho object được tạo tự động hàng loạt, ví dụ Pod sinh ra từ ReplicaSet, hoặc job chạy nhiều lần. 
    ```
    metadata:
      generateName: myapp-
    ```
  + Tiền tố ngẫu nhiên nên không đảm bảo unique -> trùng trả HTTP 409 conflict.
  + v1.31 and later: tự động thử lại 8 lần với các hậu tố khác nhau ngay trong 1 request rồi mới trả 409.

### DNS Subdomain Names
- Most resource types require a name that can be used as a DNS subdomain name as defined in RFC1123
  + contain no more than 253 characters
  + contain only lowercase alphanumeric characters, '-' or '.'
  + start with an alphanumeric character.
  + end with an alphanumeric character.

### RFC 1123 Label Names
- Some resource types require their names to follow the DNS label standard as defined in RFC 1123. This means the name must:
  + contain at most 63 characters
  + contain only lowercase alphanumeric characters or '-'
  + start with an alphabetic character
  + end with an alphanumeric character

### RFC 1035 Label Names
- Some resource types require their names to follow the DNS label standard as defined in RFC 1035. This means the name must:
  + contain at most 63 characters
  + contain only lowercase alphanumeric characters or '-'
  + start with an alphabetic character
  + end with an alphanumeric character
