# Objects in Kubernetes
- Kuberntes objects are persistent entities (thực thể bền vững) in the Kubernetes system. Kubernetes uses these entities to represent (đại diện) the state (trạng thái) of your cluster.

## Understanding Kubernetes objects
- Kubernetes objects are persistent entities in the Kubernetes system - nghĩa là không biến mất khi ngắt kết nối kubectl, API server bị restart, hay khi node bị reboot. Kubernetes uses these entities to represent the state of your cluster.
  + What containerized applications are running (and on which nodes)
  + The resources available to those applications.
  + The policies around how those applications behave, such as restart policies, upgrades, and fault-tolerance (khả năng chịu lỗi).
- A Kubernetes object is a `record of intent (ý định)` -- once you create the object, the Kubernetes system will constantly work to ensurce that the object exists.
  + Khi tạo 1 object (deployment với replicas:3) -> ghi lại 1 ý định `tôi muốn trạng thái của cluster luôn là 3 pod đang chạy`
  + Kubernetes liên tục theo dõi và tự động điều chỉnh để trạng thái thực tế (actual state) luôn khớp với trạng thái mong muốn (desired state) đã khai báo trong object đó.
```
-> Yaml (desired state) 
  -> kubectl/client library 
    -> Kubernetes API (kube-apiserver) 
      -> Object lưu vào etcd (persistent) 
        -> Controller liên tục reconcile: actual state ~ desired state 
          -> Cluster tự động kéo về trạng thái mình muốn
```
### Object spec and status
- Kubernetes object includes two nested object fields that govern the object's configuration: the object `spec` and the object `status`
#### Spec
- For objects that have a `spec`, you have to set this when you create the object, providing a description of the characterristics you want the resource to have: its desired state
  + `spec ~ specification` -> ghi lại desired state
  + Configmap và Secret không cần spec (chỉ có data) vì không mô tả một trạng thái mong muốn cần được duy trì (reconcile), chúng chỉ là dữ liệu tĩnh.
#### Status
- The status describes the current state of the object, supplied and updated by the Kubernetes system and its components.
  + `status` do hoàn toàn kubernetes tự động điền và cập nhật.
  + Trạng thái thực sự của objectm do các controller k8s quan sát ghi lại.

#### Control plane
- The Kubernetes control plane continually and actively manages every object's actual state to match the desired state you supplied.
```
spec (bạn viết)  ──────┐
                        ├──→  Controller liên tục SO SÁNH
status (hệ thống viết) ──────┘
                        ↓
              Nếu status ≠ spec
                        ↓
        Controller HÀNH ĐỘNG để kéo status khớp lại spec
```
```
for {
    desired := đọc spec từ object
    actual  := quan sát trạng thái thật của cluster
    if actual != desired {
        thực hiện hành động để actual tiến gần desired
    }
    cập nhật status = actual vừa quan sát được
    sleep(một khoảng ngắn)
}
```

### Describing a Kubernetes object
- `Yaml` -> kubectl đọc yaml -> kubectl chuyển đổi yaml thành json -> Gửi json trong HTTP request body tới kube-apiserver.
```
apiVersion: apps/v1
kind: Deployment
metadata: 
  name: nginx-deployment
spec: -> object deployment
  selector:
    matchLabels:
      app: nginx -> nhận diện pod thuộc quản lý của deployment.
  replicas: 2
  template:
    metadata:
      labels:
        app: nginx
    spec: -> object pod (template)
      containers:
      - name: nginx
        image: nginx:1.14.2
        ports:
        - containerPort: 80
```
- nested object: template.spec là 1 PodSpec được trong bên trong DeploymentSpec.

- Required fields:
  + `apiVersion`
  + `kind`
  + `metadata`
  + `spec`

### Server side field validation
- 3 mức validate qua kubectl --validate
  + `strict` (=true,default) -> báo lỗi, từ chối request
  + `warn`: chỉ cảnh báo, request vẫn được xử lý.
  + ignore (=false) -> không kiểm tra gì cả.
```
Viết manifest (.yaml)
   apiVersion + kind + metadata + spec
        ↓
kubectl apply -f file.yaml
        ↓
kubectl chuyển YAML → JSON
        ↓
Gửi HTTP request (JSON body) tới kube-apiserver
        ↓
API server chạy validation (strict/warn/ignore)
        ↓
Nếu hợp lệ → lưu object vào etcd → bắt đầu reconciliation loop
```

- `kubectl apply -f deployment.yaml` ~ `kubectl apply -f deployment.yaml --validate=strict`
